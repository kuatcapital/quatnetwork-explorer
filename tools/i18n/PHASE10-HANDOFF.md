# T18: шаг 10 — Dynamic SDK

База: опубликованный `713a619`. Девять прежних групп не переводить повторно. Английский отдельно не переводить и не принимать.

## Реализация

- Полный исходный словарь установленного `@dynamic-labs/locale 4.74.1`: **1005 ключей / 102 секции**. Три фрагмента по 335 исходных ключей объединены в `dynamicUi`: RU 1007 (включая few/many), KK 1005. EN — механическая копия исходника для структуры.
- Canonical: **EN 4416 / RU 4548 / KK 4416**, нормализованных ключей **4350 на язык**. Проверены точные исходные ключи, вложенность, параметры, URL и машинное подтверждение DELETE. Прежние значения словарей сохранены; обновлены только метаданные.
- `dynamicLocale.ts` проверяет полноту и параметры словаря до изменения ресурсов SDK. Использует публичный `Locale.getInstance()`, addResourceBundle и changeLanguage. KK поддерживается runtime; ложного приведения к типу Lang нет.
- `useDynamicLocale.ts` готовит локаль перед первым монтированием SDK и подписывается на languageChanged приложения. Повторная загрузка JSON того же языка работает. Переключение не меняет key провайдера и не пересоздаёт подключение.
- `DynamicProvider.tsx` подключает мост; auth/API/SIWE, connectors, chain IDs и ошибки поставщика сохранены. Никаких реальных подключений кошельков или средств в проверках.
- MIT attribution исходных строк и SDK: `tools/i18n/DYNAMIC-LICENSE.txt`. Прямая зависимость locale зафиксирована 4.74.1; соответствующая запись уже есть в yarn.lock.

## Исправленная ошибка SDK

В EmbeddedRevealView видимость EmbeddedWalletExport зависела от `!title.includes('Agree')`. Перевод заголовка менял поведение до принятия условий.

`patch-dynamic.mjs` заменяет условие на `Boolean(hasInjectedCredential || isPromptForExport)`, то есть на те же состояния, которыми определяется заголовок. Обе поставляемые версии модуля, js и cjs, исправляются при postinstall. Скрипт проверяет точную версию и SHA-256 каждого исходника, валидирует оба файла до записи и допускает повторный запуск. Неизвестный исходник или версия останавливают установку: при обновлении SDK патч надо пересмотреть.

Dockerfile только дополнен COPY патча перед установкой зависимостей. Docker build не выполнялась по прежнему решению владельца; контейнеры и серверы не затрагивались.
