# Локализация Quat Explorer

T18 добавляет русский (`ru`, по умолчанию) и казахский (`kk`) к исходному английскому (`en`). Надпись переключателя для казахского — KZ; код локали — `kk`. Термины согласуются с `docs/tasks/T18-glossary.md` в основном репозитории `kuatcapital/quatnetwork`.

Этот файл описывает инструменты инвентаризации и контроля. Наличие инструментов не означает завершения перевода или runtime-интеграции.

## Инвентаризация строк

После установки зависимостей проекта с TypeScript:

```bash
node tools/i18n/inventory.mjs
```

Результат — `tools/i18n/inventory.json`: статистика и список кандидатов с путём, строкой, колонкой, исходным текстом, видом и контекстом AST. Запуск детерминирован для одинаковых исходников и версии TypeScript; время запуска в отчёт не добавляется. После перевода раздела перегенерировать отчёт и проверить разницу.

Область поиска: `ui`, `lib`, `toolkit`, `pages`, `nextjs`, `configs`; расширения `.ts`, `.tsx`, `.js`, `.jsx` и их модульные варианты. Тесты, моки, fixtures, объявления типов, каталоги generated и символические ссылки пропускаются. Файлы `.env` и ключей не читаются.

Инструмент ищет:

- JSX-текст и строковые JSX-выражения;
- значения пользовательских props и свойств объектов: `title`, `label`, `description`, `placeholder`, `aria-label`, `alt`, сообщения и похожие имена;
- возможные сообщения и многословные литералы в остальном коде;
- шаблонные строки: выражения записываются отдельно, требуются осмысленные имена параметров и ручная проверка грамматики.

Это **кандидаты для ручного разбора**, а не доказательство полного покрытия. Код, CSS, URI и идентификаторы отсеиваются эвристически. Возможны ложные находки и пропуски; тексты из внешних iframe, сторонних виджетов, API, динамических импортированных данных и runtime-конфигов требуют отдельной проверки. Не удалять строки из объёма перевода лишь потому, что инструмент их не нашёл. В отчёте не назначаются ключи и не меняется UI.

Параметры для изолированной проверки инструмента:

```bash
node tools/i18n/inventory.mjs --root /path/to/fixture --output inventory.json
```

## Проверка словарей и ключей

```bash
node tools/i18n/check-locales.mjs
node tools/i18n/check-locales.mjs --json
```

Проверяются `locales/en.json`, `locales/ru.json`, `locales/kk.json`:

- строгий JSON, повторяющиеся свойства, непустые строки и группы, допустимые типы значений;
- одинаковые смысловые ключи и типы значений; `_meta` исключается из переводов;
- одинаковые имена interpolation-параметров `{{value}}`, включая режим неэкранированного параметра `{{- value}}`, и корректность скобок;
- обязательные формы plural по `Intl.PluralRules`: cardinal и ordinal;
- наличие литеральных ключей из `t('...')`, `i18n.t('...')`, `translate('...')` и `<Trans i18nKey="...">` в каждом словаре. Поддерживается alias `t` из `useTranslation` и alias импорта `Trans`.

Plural-семейства сравниваются по базовому ключу. Например, `transactions.count_one/count_other` для EN/KK и `transactions.count_one/count_few/count_many/count_other` для RU соответствуют одному смысловому ключу `transactions.count`. Набор обязательных категорий зависит от locale; опциональная `_zero` допускается. Лишние категории дают предупреждение, чтобы можно было хранить одинаковые наборы suffixed keys. Интерполяции обязательных форм одного семейства должны совпадать; `_zero` может обходиться без `{{count}}`.

Динамические ключи фиксируются для ручной проверки в JSON-выводе, но не объявляются автоматически валидными или отсутствующими. Обёртки с другими именами, сложные namespace/keyPrefix-схемы и текст, конструируемый во время работы, требуют отдельной проверки. Предпочтителен единый namespace со смысловыми разделами внутри JSON.

Для проверки словарей без обхода кода или для тестовых данных:

```bash
node tools/i18n/check-locales.mjs --skip-source
node tools/i18n/check-locales.mjs --root /path/to/fixture --locales-dir locales --json
```

Ошибка даёт exit code `1`. Успешный запуск подтверждает согласованность словарей и проверенных литеральных ссылок; качество русского/казахского и отсутствие всех непереведённых UI-строк проверяются отдельно.

Узкие тесты инструментов на временных fixtures (исходники проекта не меняются):

```bash
node --test tools/i18n/tooling.test.mjs
```

## Безопасное извлечение в код

Автоматическая правка допустима только для заранее просмотренного списка точных AST-позиций и согласованных ключей. Нельзя заменять все английские строки регулярным выражением: это затронет API-параметры, маршруты, CSS и код ABI.

Простой codemod может заменить согласованный JSX-текст/литеральный prop на `t('section.key')` внутри React-компонента с существующим `useTranslation`, проверяя исходный текст и позицию перед заменой. Правки применять справа налево по позициям, затем разобрать файл повторно. Module-level константы, шаблоны, rich text, hooks и валидаторы обрабатывать отдельно; глобальный серверный singleton с `changeLanguage()` не использовать.

Опциональный `localize-reviewed.mjs` реализует узкий вариант: **только точное однозначное совпадение с уже существующим значением `en.json`**, только JSX-текст и перечисленные пользовательские props, только внутри компонента/custom hook с телом-блоком. Он не создаёт переводы и ключи. По умолчанию выводит dry-run JSON с каждой заменой и причиной пропуска; принимает только явный список `.tsx` файлов.

```bash
node tools/i18n/localize-reviewed.mjs ui/pages/Blocks.tsx ui/blocks/BlocksContent.tsx
# Только после просмотра отчёта:
node tools/i18n/localize-reviewed.mjs ui/pages/Blocks.tsx --write
```

Добавляет или использует именованный импорт `useTranslation`, помещает `const { t: tQuat } = useTranslation()` в корневой компонент, сохраняет видимые пробелы смешанного JSX-текста и добавляет `tQuat` в литеральные зависимости `useMemo`/`useCallback`. Изменённый файл повторно разбирается AST перед записью; исходный текст перепроверяется перед write. Утилита не заменяет TypeScript/ESLint и визуальную проверку.

Пропускает классы, implicit-return компоненты, templates, `Trans`/`code`/`pre`/`script`/`style`, конфликты имён, неоднозначные значения словаря и memo без литерального массива зависимостей. `Value`, `From`, `To` требуют ручного выбора перевода по контексту. HTML entities не декодируются для совпадения: `&amp;` не объявляется равным `&`. Каталоги текущих параллельных работ — home, headers, SSR, i18n и общие даты — защищены от CLI-записи. Для них работать вручную с владельцем участка.

Дополнение 2026-10-26: существительные с отдельным английским суффиксом `s`/`es`/`ies` пропускаются codemod и переводятся целым plural-сообщением. Иначе перевод существительного может сохранить чужое окончание. Грамматику соседних JSX-узлов всё равно нужно просматривать вручную.
